Relatório de Engenharia e Refatoração

Projeto: algamoney-api

Skill Utilizada: java-design-patterns-reviewer

1. Análise e Diagnóstico

O projeto apresentava débitos técnicos críticos que impediam a evolução e a manutenção:

  • Incompatibilidade de bibliotecas (Java EE vs Jakarta EE).
  • Alto acoplamento entre camadas (Entidades dependentes de DTOs).
  • Lógica de negócio dispersa na camada de serviço.
  • Testes unitários quebrados ou mal configurados.

2. Ações de Correção Crítica

Antes da refatoração, o sistema foi estabilizado:

  • ✔ Migração completa para Jakarta Persistence e Validation.
  • ✔ Limpeza e ajuste do pom.xml para Spring Boot 3.3.2.
  • ✔ Correção dos testes unitários utilizando JUnit 5 e Mockito.

3. Refatoração Arquitetural (Execução)

Padrão Mapper

Implementação de PessoaMapper e CategoriaMapper. Centralizamos a conversão de tipos, permitindo que as entidades de banco de dados permaneçam isoladas da camada de apresentação.

Generalização do Observer (Eventos)

Refatoramos o RecursoCriadoEvent para suportar caminhos dinâmicos. Isso permitiu que o CategoriaResource passasse a usar o sistema de eventos de forma padronizada, eliminando código duplicado.

Encapsulamento de Domínio

A lógica de atualização foi movida para o modelo Pessoa. Exemplo da nova implementação:

public void atualizarDados(Pessoa novosDados) {
  if (novosDados.getAtivo() != null) this.setAtivo(novosDados.getAtivo());
  // ... demais campos encapsulados
}

4. Conclusão

A refatoração resultou em uma arquitetura mais limpa (Clean Architecture), facilitando testes unitários e futuras expansões do sistema sem a necessidade de modificar componentes core (OCP).
